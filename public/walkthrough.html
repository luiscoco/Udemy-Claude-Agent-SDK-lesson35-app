01

Input and output are separate

A string prompt still returns an asynchronous SDK output iterator. Streaming input describes how user messages enter the query, not whether response text is streamed. Partial-output rendering belongs to the next lesson.

02

Host queue policy

This app gates each yielded message on the prior actual result. Without that policy, an application that eagerly yields several inputs may see different batching or turn boundaries. The queue and SDK session are distinct layers.

03

Session lifetime and resume

Natural multi-turn context comes from one live streaming Query. String prompts can still resume a persisted session. This app uses an explicit actual session ID instead of continue, which selects the latest matching conversation. Persistence is enabled only for the resume comparison.

04

Images

Single string prompts do not directly carry image blocks. The bundled image is sent as base64 image/png in an SDKUserMessage. Its printed marker is absent from the text instruction, and actual model output provides visual evidence.

05

Interrupt versus closing input

interrupt asks the SDK to stop its current turn; closing the queue ends future input. The interruption demo waits for a real delayed Read and then recovers on the same Query. New chat starts a fresh Query; /clear is a separate SDK slash-command mechanism.

06

Actual control acknowledgement

The setter example changes default to dontAsk and awaits setPermissionMode. It exposes only a fixed Read and keeps its allow rule. The resulting Read is not evidence of unrestricted access or a model switch. setModel is another available streaming control described in the source presentation.

07

Cap and exception handling

The string loop must be drained to observe its exception after error_max_turns. The streaming comparison records the same cap result without a thrown stream error, then sends a tool-free recovery message. Budget and turn limits remain distinct controls.

08

Scope and costs

Only the disposable lesson.txt Read is available; no edits, shell commands or subagents. A $0.45 SDK budget threshold is not a prepaid cap. Interactive chat is bounded to six inputs and a six-minute host lifetime. Secrets, dependencies and teaching media remain excluded from Git.
